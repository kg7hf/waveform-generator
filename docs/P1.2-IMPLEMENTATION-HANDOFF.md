## Required P1.2 operator model

The composite device has one CDC ACM function and one microSD-backed MSC LUN.
CDC controls whether the LUN is mountable. Use this temporary, exact line
protocol for P1.2:

```text
MEDIA HOST\n
MEDIA LOCAL\n
PLAY\n
STATUS\n
```

Accept CRLF as LF. Return one bounded line beginning with `OK ` or `ERR ` for
every complete request. Use a small fixed receive buffer; reject and drain an
overlong line. Do not implement the full WFG/1 protocol in P1.2.

- `MEDIA HOST` gives the PC exclusive raw-block ownership when the card is
  ready. In the implemented recovery behavior, the same command starts one
  bounded reinitialization attempt from an uninitialized or faulted idle state;
  `OK MEDIA HOST INIT` means the host must poll `STATUS` before using the LUN.
  Firmware FatFs must be unmounted and playback must be idle.
- The host copies and verifies `WG\PLAY.WAV` and `WG\PLAY.WGM`, then flushes and
  dismounts or safely ejects the Windows volume.
- `MEDIA LOCAL` makes MSC report no medium and gives firmware exclusive card
  ownership. A SCSI eject callback may be counted, but it must not itself change
  ownership; CDC owns the mode transition. Firmware cannot flush the Windows
  filesystem cache, so never imply that the CDC command replaces the host flush
  and dismount.
- `PLAY` is accepted only in local mode. It mounts FatFs read-only, validates
  `2:/WG/PLAY.WAV`, plays it once, emits silence after the exact PCM extent,
  drains, stops the codec, closes the file, and leaves the result observable.
- `STATUS` reports card/media owner, MSC readiness, player state, first error,
  and essential counters without changing state.
- Support `MEDIA HOST` again when playback is stopped and all firmware file/FatFs
  ownership has been released. If safe repeat playback is materially larger than
  this slice, keep one playback per local-ownership cycle and reject an unsafe
  transition visibly. Never allow MSC callbacks and FatFs to access the card at
  the same time.

Boot should bring a successfully initialized card into host/MSC mode. Keep CDC
available for diagnostics when practical. Do not advertise the LUN ready until
the SD card has valid initialized geometry. A missing card must be visible in
`STATUS`; it must not silently fall back to compiled audio.

## Smallest firmware integration

Finish the draft rather than redesigning the fixture into a general storage
product. At minimum:

1. Compile the generator-local MSC adapter and the already materialized
   `third_party/tinyusb/src/class/msc/msc_device.c` only for the player image.
2. Enable one MSC instance for the player image and set
   `CFG_TUD_MSC_EP_BUFSIZE` consistently with the adapter. A 512-byte aligned
   transfer buffer is adequate for this checkpoint. Use at least 32-byte DMA
   alignment for SD buffers.
3. Make the player image a CDC-plus-MSC composite device with CDC interfaces 0/1
   and MSC interface 2. Preserve CDC endpoints `0x81`, `0x02`, and `0x82`; use
   MSC endpoints `0x03` and `0x83`. Use a distinct composite PID so Windows does
   not reuse the old CDC-only descriptor cache. Scaffold and resident-tone
   images may remain CDC-only.
4. Initialize the original-EVK USDHC1 microSD path and obtain card geometry
   before reporting the LUN ready. Use the existing locked SDMMC/FatFs sources.
   Firmware does no formatting and no filesystem writes; Windows may format a
   suitable card as FAT32 while in host mode.
5. Keep raw MSC block I/O synchronous and bounded. Validate LUN, buffer, offset,
   block size, LBA range, and transfer count. Report not-ready after local
   ownership. Handle SCSI synchronize-cache without claiming a cache flush that
   the stack did not perform. Return max LUN zero. Count safe-eject requests but
   leave ownership changes to CDC.
6. Put CDC parsing and MSC callbacks under a clear single USB-task ownership
   rule. Signal the lower-priority player task only after the mode transition is
   complete. Reject commands that would overlap raw MSC access, FatFs, or active
   codec playback.
7. Refactor the player so it does not reinitialize/reset the SD host behind the
   MSC owner. It may mount FatFs only in local mode. Close the file and unmount
   FatFs on success and failure before allowing host mode again.
8. Preserve the fixed transparent WAV behavior: exact RIFF/file size, exactly one
   `fmt ` and one `data`, bounded unknown chunks, PCM format 1, mono, 48,000 Hz,
   signed PCM16, no resampling, normalization, looping, crossfade, or resident
   fallback.

Expose at least these media counters in `STATUS` and the SWD checkpoint: media
state/owner, media error, card ready, MSC ready, block count/size, test-ready
calls, not-ready responses, read/write calls and blocks, read/write errors,
invalid/rejected requests, synchronize-cache calls, eject requests, and ownership
handoffs. Preserve the existing player/audio counters. Keep the name
`file_frames_submitted`; it means frames copied into SAI transmit request
buffers, not proven DAC completion. P1.3/P1.5 will add stronger pre-EOF ring
headroom, DMA completion, concurrency, fault, and re-arm evidence.
